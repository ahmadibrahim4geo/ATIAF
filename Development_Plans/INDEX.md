## Numbering rules
- Intake covers a user-supplied plan file with any filename and development requests written in the conversation; `PLAN_*.md` / `TASK_*.md` are examples, not filters. Discussion alone does not authorize implementation.
- Keep the supplied descriptive title/name, or derive one from the requested outcome when absent. Move the supplied file to `Active/PLAN-<NNNN>_<descriptive_name>.md` before implementation; use an English filesystem-safe name and preserve original title/requirements. Record original path/name/title and SHA256 here and in the plan. Any pristine source snapshot belongs only in `Source_Archive/` as reference-only. Do not leave supplied plans in the project root/general folders unless explicitly requested. At handoff verify relocation and index links; incomplete work remains Active/Blocked, never Completed just to clear the root.
- Allocate one greater than the highest ID in this index or any lifecycle folder. Revisions of the same work keep their ID and record an in-file revision history; do not duplicate plans. Report numbers and Journal record numbers are separate sequences.
- Only verified complete plans -> `Completed/`; incomplete -> `Active/`; blocked -> `Blocked/`; replaced -> `Superseded/` with links.
- IDs never change, repeat or get reused. Use Git `mv` when tracked; never delete history.
